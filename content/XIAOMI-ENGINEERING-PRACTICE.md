# 三、工程实践｜小米 AI 材料算法工程师

这一章替换原有的“其他活动”，不再平均铺陈会议、访问和实验室事务，改为围绕岗位要求展示材料数据、Agent 工具链和研发落地能力。

## 页面结构

1. **面向材料研发的 Agent 工具链**：材料数据底座 → 研发工具封装 → Agent Harness → 面向小米落地。
2. **材料数据底座**：国家重点研发计划课题、多源材料知识图谱、本体与可视化模块、10⁵ 级多模态材料数据库；将成分、工艺、性能和论文证据组织成研发数据服务。
3. **Agent Harness**：展示从用户问题、Intent Plan、工作流、MCP Tools、Evidence List 到回答/校验的链路。工具包括 `material_db_hybrid_search`、`paper_browser` 和 `property_predictor`。
4. **工程实现**：说明 intent planner、论文检索与证据读取、材料性能预测三个已实现工具入口，以及接口、数据结构和测试边界。
5. **面向小米的落地路线**：明确这是后续工作设想，把已有基础接入 DFT、MD、FEM、表征分析和实体实验，形成多智能体协作、证据可追溯、结果可评估的材料研发闭环。

## 口头表达边界

- MaterAgent 当前表述为“在研工程实践”，不写成已经完成的完整多智能体系统。
- MCP 工具、检索和性能预测是已有工程实现；多智能体协作、A2A 协议、DFT/MD/FEM 和实体实验室接入属于面向小米的下一步路线。
- 材料数据库项目写“参与课题、主导知识图谱/本体/可视化模块”，不把整个课题成果全部归为个人完成。
- 不在本章展开论文方法和重复的会议经历；论文成果仍由前一章承担证明作用。
